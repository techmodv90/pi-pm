# Task System V1.0.0

V1.0.0 introduces the canonical Work Item model across the Go CLI, Pi extension, scheduler, HTTP API, and Svelte dashboard.

## Model

- Aggregate types: `epic`, `feature`.
- Executable types: `task`, `bug`, `chore`, `gate`.
- Arbitrary aggregate nesting with transactional cycle validation.
- Indexed, derived readiness from status, claims, deferral, dependencies, and gates.
- Immutable staged Scan, RRI, Vision, Blueprint, Contracts, and task-graph revisions.
- Revision/hash-bound owner checkpoints and explicit implementation authorization.
- Atomic graph materialization with immutable inactive TIP revisions.
- Recursive aggregate verification and closure.
- Normalized Work Item labels with parent inheritance, usage counts, idempotent management, and AND/OR filtering across CLI, API, Pi tools, and dashboard.

## Cutover

`pic work-item` is the only production lifecycle mutation surface. Legacy Epic, Task, Task Item, Feature, and phase-repair commands are removed from production dispatch. Legacy HTTP mutation endpoints return `410 Gone`. Historical rows remain readable for migration and audit purposes.

The Pi extension exposes canonical Work Item actions and schedules only authorized, dependency-ready executable leaves. The dashboard provides a typed Work Item list and recursive detail view at `/work-item/<id>` with hierarchy, blockers, readiness, staged approvals, artifact revisions, TIP authorization, and execution evidence.

## Migration Safety

Migration is idempotent and preserves legacy IDs, relationships, reports, decisions, timestamps, artifact bytes, and content hashes. Archived Task Items are read-only. Incompatible in-progress pipelines are quarantined rather than automatically restarted.

## Verification

Release verification runs the complete Go and TypeScript suites, TypeScript checking, dashboard/runtime builds, source audits for live legacy mutation paths, and production-binary regressions proving removed commands cannot mutate storage.
