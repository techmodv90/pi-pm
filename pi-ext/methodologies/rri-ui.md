# RRI-UI — UI Design Pipeline

RRI-UI combines pre-code RRI-UX critique with post-code RRI-T D1 validation. Apply it only to user-interface work; mark it N/A with a reason for APIs, CLIs, libraries, data pipelines, and infrastructure.

- **Phase 0: Setup** — gather RRI output, approved business rules, user flows, wireframes, and proposed design.
- **Phase 1: RRI-UX Critique** — apply `rri-ux.md` before coding using risk-relevant UX persona, dimension, and Flow Physics combinations.
- **Phase 2: Design Iteration** — update Blueprint/Contracts from accepted findings and obtain owner approval. Blocking findings prevent implementation.
- **Phase 3: RRI-T Validation** — after implementation and review, apply `rri-t.md` with mandatory D1 UI/UX coverage, responsive checkpoints, interaction states, and accessibility evidence.
- **Phase 4: Final Polish** — fix or explicitly defer remaining ACCEPTABLE/PAINFUL findings; FAIL blocks acceptance.

RRI-UX finds experience defects before coding. RRI-T proves the implemented interface is correct afterward.
